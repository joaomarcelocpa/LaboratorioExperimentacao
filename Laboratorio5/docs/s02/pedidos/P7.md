# P7 — Reenvio sem duplicar (idempotência)

**Tipo:** Cabe na arquitetura
**Ordem na coleta completa:** definida no protocolo congelado

---

[CONTEXTO] O projeto está no diretório atual.

[NECESSIDADE] Clientes às vezes reenviam uma requisição porque a primeira parece ter falhado
(timeout, queda de rede). O sistema deve aceitar o reenvio sem criar entradas duplicadas,
garantindo que a operação seja executada exatamente uma vez.

[COMPORTAMENTO PARA O USUÁRIO] Ao criar uma tarefa, o cliente pode incluir um identificador
único de requisição no cabeçalho HTTP `Idempotency-Key`. Se a mesma chave for enviada mais
de uma vez, o sistema devolve a resposta original e não cria tarefa duplicada. A tela de
criação de tarefas (campo com `data-testid="idempotency-key"`) pode exibir ou gerar essa
chave para o usuário. Requisições sem o cabeçalho funcionam como antes, sem garantia de
idempotência.

[CRITÉRIOS DE ACEITAÇÃO]
- Enviar duas requisições idênticas de criação de tarefa com a mesma `Idempotency-Key` em
  sequência resulta em uma única tarefa criada e dois retornos 201 com o mesmo corpo.
- Enviar a mesma `Idempotency-Key` com payload diferente retorna 422 (conflito de chave).
- Requisições de criação sem `Idempotency-Key` continuam funcionando normalmente.
- Listar tarefas após dois envios com mesma chave retorna apenas 1 tarefa.

[SAÍDA] Implemente a mudança no próprio projeto. O resultado será verificado por testes
automatizados de comportamento.

## Mínimo observável

| Elemento | Identificador |
|---|---|
