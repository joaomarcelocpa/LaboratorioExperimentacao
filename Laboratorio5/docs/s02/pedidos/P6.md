# P6 — Permissões por papel

**Tipo:** Tensiona a arquitetura
**Ordem na coleta completa:** definida no protocolo congelado

---

[CONTEXTO] O projeto está no diretório atual.

[NECESSIDADE] Nem todos os usuários podem fazer tudo no sistema. Gestores podem criar,
atualizar e excluir tarefas; colaboradores só podem marcar tarefas como concluídas.
Usuários não autorizados não devem conseguir executar operações restritas.

[COMPORTAMENTO PARA O USUÁRIO] O sistema reconhece o papel do usuário pelo cabeçalho HTTP
`X-Papel` (valores: `gestor` ou `colaborador`). Um colaborador que tente criar, atualizar ou
excluir uma tarefa recebe uma resposta de não autorizado. Um gestor pode executar todas as
operações. Sem o cabeçalho, o sistema usa o papel padrão `colaborador`.

Na interface, o campo com `data-testid="papel-usuario"` mostra o papel ativo e os botões de
criação, edição e exclusão ficam visíveis apenas para gestores.

[CRITÉRIOS DE ACEITAÇÃO]
- Com papel `gestor`, criar, atualizar, concluir e excluir uma tarefa retornam os status HTTP
  de sucesso normais (201, 200, 200, 204).
- Com papel `colaborador` ou sem cabeçalho `X-Papel`, criar uma tarefa retorna 403; atualizar
  retorna 403; excluir retorna 403; concluir retorna 200.
- O campo `data-testid="papel-usuario"` mostra o papel ativo.
- Os botões de criar, editar e excluir aparecem apenas quando o papel é `gestor`.

[SAÍDA] Implemente a mudança no próprio projeto. O resultado será verificado por testes
automatizados de comportamento.
