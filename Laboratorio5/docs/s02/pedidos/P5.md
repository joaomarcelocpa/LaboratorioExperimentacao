# P5 — Histórico de alterações de uma tarefa

**Tipo:** Tensiona a arquitetura
**Ordem na coleta completa:** definida no protocolo congelado

---

[CONTEXTO] O projeto está no diretório atual.

[NECESSIDADE] Os usuários precisam saber quem alterou uma tarefa, quando e o que mudou,
para rastrear decisões e corrigir erros de edição.

[COMPORTAMENTO PARA O USUÁRIO] Na tela de uma tarefa, o usuário acessa o histórico de
alterações (identificador de interface: `data-testid="historico-tarefa"`). O histórico lista
cada mudança registrada, com o campo alterado, o valor anterior, o valor novo e o momento da
alteração, em ordem cronológica inversa. A tela de tarefas continua funcionando normalmente.

Pela API, o endpoint `GET /tarefas/{id}/historico` devolve a lista de alterações da tarefa.

[CRITÉRIOS DE ACEITAÇÃO]
- Criar uma tarefa, atualizá-la duas vezes com campos diferentes e consultar o histórico retorna
  exatamente 2 entradas, cada uma com campo, valor anterior, valor novo e timestamp.
- Concluir uma tarefa gera uma entrada no histórico com campo `status`, valor anterior `PENDENTE`
  e valor novo `CONCLUIDA`.
- O histórico de uma tarefa inexistente retorna 404.
- Excluir uma tarefa não apaga o seu histórico por pelo menos 1 segundo após a exclusão.

[SAÍDA] Implemente a mudança no próprio projeto. O resultado será verificado por testes
automatizados de comportamento.
